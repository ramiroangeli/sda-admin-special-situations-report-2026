# Report Brief — NDIS Specialist Disability Accommodation Administration Report 2026

Status: PLANNING DRAFT, revision 3 (aligned to skeleton v0.5 / draft_v0.3 "Editorial
Lock"). This brief records the core analytical structures the report is built on. It is
not final copy. Framework wording will be refined once mapped into
`content/page_04.md`–`content/page_22.md` and reviewed by Steve.

**Revision 3 changes** (terminology sync only — see
`draft_v0.3/EDITORIAL_LOCK_CHANGELOG.md` for full detail; no claim or evidence content
changed): "value anchors" is renamed **value reference points** throughout — "anchor"
language and any upper/lower, vertical-stack visual implied SDA in-use value must
exceed alternative-use value, which the evidence does not establish (they can differ
materially in either direction). Page 14 is reconceived from a "leakage" diagram (which
contradicted page 12's own deliberately non-ordinal framing) to a plain list of what
affects the Current Recovery Position. Page 19's packaging step is now an adaptable
"establish initial strategy," not a one-time "determine... before, not during."
Framework 2's Capital Structure and Fundamental Asset categories are described more
generally, without presupposing facts about any given case.

**Revision 2 changes** (see `ARCHITECTURE_CHANGELOG_v0.3_to_v0.4.md` for full detail):
the report now names only **three** major frameworks, to protect the 15-minute read
budget. Other analytical devices remain in the report but are referred to
descriptively (a revenue chain, an NOI bridge, value reference points, an occupancy
matrix, a sale-readiness checklist, a decision tree), not branded as named/numbered
frameworks. The former "Income Reality Bridge" is now two distinct descriptive devices
on two pages (page 8's revenue chain, page 11's NOI bridge). The former "Three Value
Lenses" is retired in favour of two formal value reference points plus a descriptive
"Current Recovery Position" that is explicitly not a third valuation methodology.

## 1. North Star

Primary readers: restructuring partners; receivers/controllers; voluntary
administrators; secured lenders/credit executives; restructuring and insolvency lawyers;
turnaround advisers; special-situations investors.

In ~15 minutes, the reader must be able to answer:

1. What am I dealing with?
2. What can go wrong?
3. Where is the value?
4. What should I do next?

Every substantive page must help answer at least one of those four questions. This is a
commercial SDA guide, not legal advice and not a general SDA market report.

## 2. The three named frameworks

The public report has exactly three named, branded, capital-letter frameworks. Every
other analytical device is real, evidenced, and used — it is just introduced
descriptively rather than branded, so the reader is not asked to hold seven named
structures in their head at once (see `SKELETON_EVIDENCE_REVIEW.md` Finding 7).

### Framework 1 — The SDA Alignment Chain

**What has to line up.**

```text
FREEHOLD PROPERTY
↓
SDA ENROLMENT / CERTIFICATION
↓
PARTICIPANT-SPECIFIC FUNDING
↓
ACTUAL OCCUPANCY
↓
PROVIDER / CONTRACTS
↓
CLAIMS / CASH COLLECTION
↓
OPERATING COSTS
↓
TRANSACTION VALUE
```

Purpose: shows the reader that SDA value is not a single fact about a building — it is a
chain of dependencies, any one of which can be broken independently of the others. Maps
primarily to pages 5, 8, 9, 11, 12.

Evidence: SUPPORTED (ADM-005-01) via SDA Rules 2020 Part 3 (EV-PUB-05/12, PUB-03) —
enrolment, participant residency, design-category alignment and other conditions are
all independently required for funding; corroborated by INT-01, INT-05. No longer only
an SDAHC analytical construct.

### Framework 2 — The Four Types of Impairment

**What is actually impaired.** `STEVE VALIDATION REQUIRED`

1. Operational
2. Provider / Contractual
3. Capital Structure
4. Fundamental Asset

Purpose: gives the reader a diagnostic taxonomy for "what exactly is wrong with this
asset." This taxonomy has not yet been validated against SDAHC's actual case
experience — see `steve_review_questions.md` / `draft_v0.3/review_manifest.yaml` Q3.
Do not treat as final. Maps primarily to pages 13, 14, 17, 21.

Category descriptions were generalised in draft_v0.3: Capital Structure no longer
presupposes operating performance is otherwise "sound" ("ownership, debt or security
arrangements constrain recovery independently of, or in addition to, operating
performance"); Fundamental Asset no longer names specific defects like "wrong
location" ("location, design category, configuration or realistic participant demand
does not support the original SDA proposition"). Same four category names, same
STEVE_VALIDATION_REQUIRED status — this was a definitional precision fix, not a
taxonomy change.

**This framework answers a different question from Framework 3.** The Four Types of
Impairment is a diagnosis — "what is broken?" It is not, and should not be presented as,
a relabelling of the six operating stages in Framework 3, and it is not validated or
invalidated by comparison to INT-09's six real-world advisory workstreams (portfolio/
debt reconciliation, income/operating review, provider strategy, asset performance/
stabilisation, debt/lender strategy, divestment decision) — that workstream model is
useful reference material for Steve's review, not a competing taxonomy to reconcile
against. Page 7 owns the operating pathway; page 13 owns the diagnosis; page 21's
decision tree connects a page-13 diagnosis to a recommended pathway, sitting inside the
Framework 3 sequence rather than beside it.

### Framework 3 — Secure → Reconcile → Diagnose → Stabilise → Value → Decide

**What to do.**

```text
SECURE
→ RECONCILE
→ DIAGNOSE
→ STABILISE
→ VALUE
→ DECIDE
```

Purpose: the operating sequence for an appointment-holder in the first month. Maps
primarily to pages 6, 7, 22.

Evidence: SUPPORTED_WITH_QUALIFICATION (ADM-007-01) via INT-09, INT-06. INT-09 adds a
material, evidenced qualification: "advisory and divestment work may need to proceed in
parallel where time pressure is material. A sequential model of 'fix everything, then
consider sale' is not always economically rational." Present the six steps as the
report's default reading order, not as a rule that must be followed lock-step — page 7
and page 17 both carry this qualification explicitly.

## 3. Descriptive analytical devices (not branded frameworks)

These are real, evidenced structures the report uses — they are just named plainly
rather than capitalised/numbered, to keep the framework count at three.

### The revenue chain (page 8 — "From Maximum SDA Price to Actual Cash")

```text
MAXIMUM / ENROLLED SDA PRICE
↓
PARTICIPANT-SPECIFIC FUNDING
↓
FUNDING ALIGNED WITH THE DWELLING
↓
PHYSICAL OCCUPANCY
↓
CLAIMABLE INCOME
↓
CASH ACTUALLY RECEIVED
```

Answers: **is the revenue real?** Deliberately stops at cash actually received — it
does not reach, and should not be labelled, "sustainable NOI." That is the NOI bridge's
job, on page 11. Evidence: SUPPORTED for the maximum-price mechanics (ADM-008-01, now
via EV-PUB-03/11, PUB-02) through to SUPPORTED_WITH_QUALIFICATION for who bears the
resulting risk (ADM-008-02 — an evidenced inference, not a source's own explicit
statement; see `evidence_claim_crosswalk.md`).

### The NOI bridge (page 11 — "From Actual Income to Sustainable NOI")

```text
ACTUAL GROSS INCOME
↓
NORMALISATIONS
↓
PROVIDER / MANAGEMENT COST
↓
PROPERTY OPERATING COST
↓
NORMALISED VACANCY
↓
R&M
↓
CAPEX
↓
ONE-OFF / NON-RECURRING ITEMS
↓
SUSTAINABLE NOI
```

Answers: **what does the asset actually earn on a sustainable basis?** This is INT-04's
own evidenced nine-step bridge (`evidence_notes/internal_evidence/INT-04_income_noi_patterns.md`),
used directly rather than paraphrased into a different, more theoretical bridge — see
`ARCHITECTURE_CHANGELOG_v0.3_to_v0.4.md` for why the report previously carried two
different, overlapping "bridges" across pages 8 and 11. Starts from actual gross income
(not headline price), because occupancy, funding alignment and claiming are already
covered by page 8/9 by the time the reader reaches this bridge. No universal
percentages at any step (direct guardrail against HOLD-05).

### The value reference points (page 12 — "Two Value Reference Points — and the Current Recovery Position")

**Renamed from "value anchors" in draft_v0.3.** "Anchor" language, and any visual that
stacks the two references vertically (high to low), implied SDA in-use value must
exceed alternative-use value — the evidence does not establish that; they can differ
materially in either direction, depending on location, design and local demand. Two
formal, independently evidenced values, not three equally-weighted lenses (the former
"Three Value Lenses" concept is retired — see `SKELETON_EVIDENCE_REVIEW.md` Finding 6
and the changelog):

- **SDA In-Use Value Reference.** A valuation of the asset operating under adopted
  assumptions: occupancy, funding, provider performance, cost structure.
- **Alternative-Use / Underlying Property Value Reference.** A valuation of the
  underlying property under the relevant alternative-use assumptions.

Between them sits the **Current Recovery Position** — explicitly a commercial/
transaction assessment, not a third independent valuation methodology. It may be
affected by: actual occupancy; participant funding; provider position; contractual
friction; required CAPEX; lease-up/stabilisation period; transaction execution risk;
holding cost. Present the visual non-ordinally — both references feeding the Current
Recovery Position from the sides, never stacked high-to-low:

```text
SDA IN-USE VALUE REFERENCE          ALTERNATIVE-USE PROPERTY VALUE REFERENCE
                 \                          /
                  \                        /
                   CURRENT RECOVERY POSITION
                (commercial estimate — not an
                   independent valuation)
```

Evidence: the two references are strongly evidenced independently by
`evidence_notes/internal_evidence/INT-05_valuation_patterns.md` ("In-use SDA value and
alternative-use value can be materially different," professional valuations reviewed by
SDAHC separately assess both). The Current Recovery Position between them is SDAHC's own
commercial interpolation — real and useful, but not independently evidenced as a
distinct valuation output the way the two references are; do not present it with the
same formal weight. Maps primarily to pages 12, 17. (Page 14 is now a related but
distinct device — see below.)

### What affects current recoverability (page 14 — "What Affects Current Recoverability?")

**New in draft_v0.3, replacing the retired "value leakage" diagram.** Page 14 previously
showed value "draining" left-to-right from the SDA in-use value reference to the
Current Recovery Position — a directional, ordinal framing that silently contradicted
the value reference points' own non-ordinal design. It is replaced with a plain list of
what affects the Current Recovery Position: vacancy/occupancy, participant funding,
provider position, operating costs, CAPEX/compliance, holding time/carry, contractual
friction, transaction execution risk. The page states explicitly that the Current
Recovery Position does not necessarily start at, or move toward, the SDA in-use value
reference. Each of the four sources of impairment (Framework 2) tends to affect a
different subset of these factors — that link is retained. No percentages, consistent
with the guardrail against HOLD-05. Maps to page 14.

### The occupancy matrix (pages 9, 18)

Page 9 (educational/economic mechanics — **why can an occupied place still
underperform?**) and page 18 (decision/triage — **what quality of occupancy do I
actually have?**) use the same underlying evidence
(`INT-04_income_noi_patterns.md`, `INT-07_occupancy_patterns.md`) at different depths.
Page 9 introduces the mechanism once, briefly; page 18 does the triage work and feeds
page 17. See each page's planning file for the explicit division of labour — avoid
duplicated explanatory copy between them.

### The sale-readiness checklist (page 15) and market-readiness sequence (page 19)

Page 15 (**do I possess defensible evidence?** — data room, evidence completeness) and
page 19 (**should I launch now?** — verify → reconcile → resolve material issues →
prepare data room → set defensible economics → establish initial packaging strategy →
launch) both draw on `INT-08_transaction_readiness_patterns.md`. Page 15 is the audit;
page 19 is the action once "sell" has been decided. Both pages' trigger points were
corrected in draft_v0.2/v0.3 to stay consistent with the operating pathway's
parallel-execution allowance: page 15 now reads "before broad market launch or formal
buyer due diligence" (not "before any sale process"), and page 19's final step reads
"establish initial packaging strategy... while retaining the ability to adapt it as
credible market evidence emerges" (not "determine packaging before, not during, the
process" — packaging is not a one-time, irreversible decision). See each page's
planning file.

### The decision tree (page 21)

Connects a page-13 diagnosis (which impairment type predominates) to a recommended
pathway. Entirely downstream of Q3 — see Framework 2 above.

## 5. Evidence taxonomy

```text
P1 = publicly verified primary evidence
P2 = direct documentary SDAHC evidence
P3 = direct first-hand market intelligence
P4 = multiple independent market signals
P5 = single-source / unverified intelligence
```

Publication rules:

- P1/P2 may potentially support factual publication.
- P3/P4 must only be used in aggregated/anonymised form and clearly framed as such.
- P5 is internal decision support only — never publication-ready on its own.

Publication status tags (independent of evidence class):

```text
PUBLIC
CONFIDENTIAL_INTERNAL
ANONYMISED_PUBLICABLE
NOT_PUBLICABLE
```

Public evidence integration (this revision): six public evidence notes (PUB-01–PUB-06,
drawn from NDIA, the Federal Register of Legislation and ASIC) now supply verified P1
citations — either a locally-held primary file (PUB-01, pointing to the NDIA Supplement
P workbook already in the repository) or an official government/regulator URL not yet
frozen as a local copy (PUB-02–PUB-06). See `evidence_register.csv` and
`source_manifest.yaml`. All five claims previously blocked as
`PUBLIC_SOURCE_STILL_REQUIRED` are now resolved — see `evidence_claim_crosswalk.md`.
